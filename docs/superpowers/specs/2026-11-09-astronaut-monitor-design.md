# Astronaut Health Monitor: дизайн-спецификация

Дата: 2026-11-09 · Хакатон: NASA Space Apps Challenge, Ташкент, 14–15.11.2026
Статус: дизайн утверждён в диалоге, спецификация записана.

## 1. Цель и критерии успеха

Собрать ПО для мониторинга здоровья астронавтов во время космических миссий: дашборд «Mission Control», который показывает телеметрию экипажа из четырёх человек, реагирует на аномалии и работает на реальных открытых данных NASA.

Успех:
1. Демо на 3–5 минут, где каждая кнопка работает.
2. Видно, что данные реальные (PhysioNet, NASA DONKI), с честной атрибуцией: реальное событие, смоделированный отклик.
3. Система не падает ни при каких условиях, в том числе без сети.
4. Интерфейс строгий, дорогой, не похож на админ-шаблон.

Допущения:
- Это демонстрационный дашборд, а не медицинский прибор. Живых датчиков нет.
- Состав команды: один fullstack-разработчик (весь код) и двое математиков-аналитиков (код не пишут, дают спецификации, см. Приложение A).
- Датасеты неизвестны заранее, поэтому все данные скачиваются в репозиторий до хакатона и не зависят от сети.

## 2. Архитектура

Монорепо на pnpm workspaces:

```
apps/web          Next.js (App Router) + TypeScript, Tailwind v4, shadcn/ui
apps/api          NestJS: WebSocket-gateway + REST
packages/engine   чистый TypeScript: схемы Zod, плеер, модификаторы, правила аномалий
packages/data     скрипты ингеста + готовые scenario-pack.json, thresholds.json
docs/             спецификации и планы
```

Ключевое решение: `packages/engine` без зависимостей от React и Nest. Его импортируют и сервер, и браузер. Поэтому встроенный симулятор в оффлайне — тот же код, что на сервере.

БД и ORM не используются. Данные лежат статикой в `packages/data`, журнал событий хранится в памяти сервера и в `persist` на клиенте.

## 3. Движок и контракты данных

Кадр телеметрии — чистая функция: `frame(t) = baseline(t) + активные модификаторы(t)`.

- **baseline**: реальные записи PhysioNet, по одной на каждого астронавта (BIDMC для HR/SpO₂/дыхания/PPG, MIT-BIH для ЭКГ). Запись зацикливается.
- **Модификаторы**: создаются кнопками Control Deck и сценариями. Каждый имеет начало, длительность и огибающую: солнечная вспышка (доза), нагрузка (HR вверх, HRV вниз), сбой O₂ (SpO₂ вниз).
- **Журнал событий**: список `{ t, type, crewId, params }`, питает Audit Log и Time Travel (любой момент вычисляется как `frame(t)` по журналу).

```ts
TelemetryFrame {
  t: number                    // MET, секунды
  crewId: string
  vitals: { hr, hrv, spo2, bpSys, bpDia, respRate, temp, stress, eeg }
  ecg: number[]                // чанк сэмплов для отрисовки
  radiation: { doseRateUSvH, cumulativeMSv }
  cabin: { co2, o2 }
  status: { overall, byMetric }   // NOMINAL | CAUTION | WARNING | CRITICAL
  degraded: boolean            // true, если значения подставлены по умолчанию
}
ScenarioPack {
  meta: { id, title, sources[], licenses[] }
  tickHz, durationSec
  baselines: Record<crewId, ref>
  events[]                     // предзаписанные эпизоды (реальная вспышка DONKI)
}
Alert { id, t, crewId, metric, severity, message }
```

Валидация через Zod с `.catch(default)`. Некорректное значение заменяется последним валидным и помечается `degraded: true`.

**Правила аномалий.** Пороги лежат в `packages/data/thresholds.json` (заполняют математики), не в коде. Движок считает статус метрики, статус астронавта (худший из метрик) и глобальный статус миссии. Гистерезис: порог выхода мягче порога входа, чтобы статус не дёргался на границе. На переходы статусов генерируется `Alert`, из которого растут тост Sileo, голос и запись в журнал.

**Объём потока.** ЭКГ ~360 Гц передаётся чанками 10 раз в секунду (~36 сэмплов). Остальные показатели 1–2 раза в секунду.

## 4. Транспорт и отказоустойчивость

Интерфейс `TelemetrySource`: `start()`, `stop()`, `onFrame(cb)`, `onHealth(cb)`. Над ним `SourceManager`, конечный автомат:

```
LIVE (WebSocket, Nest) → POLL (REST раз в 500 мс, TanStack Query; опционально)
  → STALE (последние значения затемнены, до 5 с) → SIM (engine в браузере)
```

- Нет heartbeat 3 с — уходим вниз. Фоном повторные попытки с экспоненциальной паузой.
- Баннер в SIM: `SIGNAL LOST — USING ESTIMATED TELEMETRY`.
- При возврате в LIVE сервер главный: клиент принимает его `t` и журнал. Команды оператора, нажатые в оффлайне, ставятся в очередь и отправляются после реконнекта.
- POLL добавлен потому, что на площадках WebSocket часто блокируется, а HTTP проходит.

Изоляция сбоев:
- Каждый виджет обёрнут в `WidgetBoundary`: при падении заглушка `Telemetry channel offline` и кнопка «Reconnect». Корневой `error.tsx` как последний рубеж.
- Валидация Zod выполняется по каждому астронавту отдельно: битые данные одного помечают только его канал как `degraded`.

Защита от ошибок оператора:
- Кнопки Control Deck — hold-to-confirm (удержание ~0,8 с, заполняющееся кольцо).
- Голос (`speechSynthesis`) и звук разрешены браузером только после действия пользователя: на старте экран «Enter Mission Control» включает аудио.

## 5. Состояние на клиенте

- Zustand `useMissionStore`: выбранный астронавт, режим симуляции, алармы, состояние источника; `persist` в localStorage.
- Кольцевые буферы кадров (~500 тиков на астронавта) живут вне React-состояния; из них читают Time Travel и графики.
- ЭКГ и скан тела обновляются через `ref` и `requestAnimationFrame`. Числовые виджеты — 2–4 раза в секунду через точечные селекторы.

## 6. UI и визуальный язык

Палитра:

| Токен | Значение | Роль |
|---|---|---|
| Ink | `#0B1220` | основа фона |
| Slate | `#141C2E` / `#1C2740` | панели (glassmorphism, blur) |
| Mist | `#9FB0C9` | вторичный текст, линии |
| Bone | `#E8EDF5` | основной текст, числа |
| Signal teal | `#4FB6A8` | единственный фирменный акцент (штатно) |
| Amber / Coral / Deep red | `#D9A441` / `#D9645A` / `#B8323F` | WARNING / CRITICAL / EMERGENCY |

Статус всегда дублируется текстом или иконкой. Контраст по WCAG AA. Тема только тёмная; `prefers-reduced-motion` уважается.

Шрифты: Hanken Grotesk (интерфейс), Martian Mono (только показания, табличные цифры).

Главный образ: жидкая капля статуса перетекает между аватарами экипажа и «вытягивается» в Dynamic-Island плашку наверху при аномалии. Gooey-фильтр применяется только к малым элементам (рейл экипажа, плашка). Фон — дешёвый CSS-градиент, меняющий оттенок по глобальному статусу (шейдерный фон не делаем).

Раскладка:

```
┌───────────────────────────────────────────────────────────┐
│ MET 003:14:22  ◉ Link 42ms     [  ISLAND PILL  ]   NOMINAL │
├────────┬──────────────────────────────────┬───────────────┤
│ CREW   │  Body Scan (SVG, hot-spots)      │ CONTROL DECK  │
│ ●  A1  │  ECG sweep (canvas)              │ [Solar flare] │
│ ●  A2  │  SpO₂ │ BP │ Stress │ EEG        │ [Exertion]    │
│ ●  A3  │  Radiation (cumulative)          │ [O₂ fault]    │
│ ●  A4  │                                  │ [Normalize]   │
│        │                                  │ Audit Log     │
├────────┴──────────────────────────────────┴───────────────┤
│ Time Travel  ──────────●───────────────  −24h          now │
└───────────────────────────────────────────────────────────┘
```

Клик по органу на силуэте подсвечивает соответствующий график и показывает микро-метрики в Sileo-плашке.

Анимации: motion и Sileo — переходы UI, тосты, реакции кнопок; Anime.js — только отрисовка SVG-путей (линия ЭКГ, эффект сканирования). Числа — `@number-flow/react`.

Иконки: lucide-react. Тосты: Sileo в `layout.tsx` (библиотека построена на motion).

Мультиязычность: английский по умолчанию, словари `ru` и `uz` через `next-intl`; макет проверяется на длинных строках.

## 7. Источники данных и риски

| Источник | Что даёт | Риск |
|---|---|---|
| PhysioNet: MIT-BIH, BIDMC | Реальные ЭКГ, PPG, HR, SpO₂, дыхание | Низкий. BIDMC, вероятно, в CSV; MIT-BIH — WFDB (формат 212), парсер на TS ~60 строк |
| NASA DONKI (`api.nasa.gov/DONKI/FLR`, `/SEP`) | Метаданные событий: класс вспышки, начало/пик/конец | Средний. Дозы в мЗв нет — профиль дозы моделируется |
| NASA OMNIWeb | Потоки протонов, параметры солнечного ветра | Средний. Основа для профиля дозы |
| NASA OSDR / GeneLab | Омика, биомаркеры, научный контекст | Высокий как источник сигналов. Использовать только как справочный слой |
| NASA-STD-3001 | Пороговые значения | Низкий. Числа выписываются вручную из первоисточника на `standards.nasa.gov` |

Правила честности на питче: доза радиации — «реальное событие DONKI, смоделированный отклик»; в `meta.sources` и `meta.licenses` каждого пака перечисляются источники и лицензии (проверить на странице каждого датасета).

## 8. Тестирование

- Vitest на `packages/engine`: детерминизм кадров, гистерезис порогов, Zod-фолбэки.
- Один смоук-тест Playwright, проходящий сценарий демо целиком.
- Визуальная проверка графиков и анимаций вручную в браузере.
- Учения на отказ: остановить сервер, подать битый JSON, отключить сеть.
